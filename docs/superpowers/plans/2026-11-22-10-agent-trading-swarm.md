# Orion Algo: 10-Agent Autonomous Trading Swarm Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an institutional 10-Agent Autonomous Trading Swarm for Orion Algo that models a hedge fund trading floor with specialized agents (Regime Scanner, Technical Quant, Options Greeks, Institutional Flow, Macro Sentinel, RMS Guardian, Execution Sniper, Capital Allocator, Statistical Arbitrage, and Performance Auditor) collaborating to analyze markets, achieve quorum consensus, and execute risk-protected trades.

**Architecture:** 10 autonomous Python agent classes inherit from a unified `BaseAgent` abstraction in `backend/app/services/agents/`. Each agent independently analyzes market streams, computes mathematical indicators/Greeks/flows, and casts a directional vote with a conviction score `[0.0, 1.0]`. A `SwarmCoordinator` aggregates signals, calculates weighted consensus (requiring $\ge$ 65% conviction), and passes winning setups through the `RMSGuardianAgent` (which possesses absolute veto power for SEBI limits and daily loss ceilings). Approved orders are dynamically sized by the `CapitalAllocatorAgent` and routed to paper or live broker gateways by the `ExecutionSniperAgent`. REST endpoints expose real-time swarm deliberation and a Next.js 16 War Room UI provides visual oversight.

**Tech Stack:** Python 3.12 (FastAPI, NumPy, Pandas, Asyncio, Pytest, Pydantic), Next.js 16 (React 19, TypeScript, Tailwind CSS, Lucide Icons), Supabase PostgreSQL.

**Spec:** `docs/superpowers/specs/2026-11-22-10-agent-trading-swarm-design.md`

## Global Constraints

- Every trade signal generated by the swarm must pass through the `RMSGuardianAgent` veto gate before reaching execution; no bypass is permitted.
- If cumulative daily realized/unrealized loss reaches the ₹10,000 ceiling, the `RMSGuardianAgent` must veto all new orders and trigger the emergency Kill Switch.
- The minimum quorum threshold to recommend a trade is 65% weighted conviction across directional agents.
- All 10 agents must output standard `AgentVote` structures containing `agent_name`, `signal` (`BUY`|`SELL`|`HOLD`), `conviction` (`0.0` to `1.0`), and human-readable `reasoning`.
- All backend tests must pass with `pytest` without regressions to existing paper matcher, risk manager, or backtest engines.

## Review Focus

1. **Agent Consensus Deadlock:** In choppy or conflicting markets, agents cast contradictory votes resulting in infinite deadlock. *Expected:* The `SwarmCoordinator` outputs a definitive `HOLD` signal with neutral market state when conviction is $< 0.65$.
2. **RMS Veto Bypass Vulnerability:** If a high-conviction (e.g. 95%) trade is proposed during high volatility, execution proceeds despite risk violations. *Expected:* The `RMSGuardianAgent` has unconditional veto authority that halts any trade violating max daily loss, cooldown, or the 15:15 IST cutoff regardless of 99% conviction.
3. **Macro Event Blackout Slip:** High-impact economic events (RBI MPC rate announcement) cause severe slippage and whipsaws. *Expected:* `MacroSentinelAgent` imposes a `BLACKOUT` state within 30 minutes of scheduled events, freezing new entries.
4. **Options Expiry Theta Decay Miscalculation:** Directional options buys on expiry day suffer 100% premium loss from theta decay. *Expected:* `OptionsGreekAgent` detects high theta decay on expiry afternoon and switches recommendations to defined-risk spreads or equity intraday.
5. **Memory Leak in Swarm History:** High-frequency deliberation logs cause server memory inflation over extended daemon uptime. *Expected:* The coordinator maintains a bounded rolling ring buffer (max 200 deliberation logs).
